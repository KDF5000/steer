# 足迹：Steer 原生风格概览原型

日期：2026-10-25。状态：待用户确认的实现参考；未修改应用代码、数据库或服务接口。

## 入口与交付物

直接打开 `index.html`，无需构建或联网。`styles.css` 复用仓库已有 Geist 字体资源（相对路径位于 `../workbench-visual-refresh/assets`）；移动原型时需一起携带资源。`app.js` 仅包含固定示例数据与交互。截图 `overview-desktop.png` / `report-desktop.png` / `overview-mobile.png` 用于静态评审，HTML 是交互和布局参考。

不引入新的工作页或任务实体。现有「工作日志」导航位置改为「足迹」。正式开发前需明确旧日志内容的保留与入口迁移，不直接覆盖旧数据。

## 对齐真实页面的依据

- `app/fusion/fusion.css`：根部颜色变量、侧栏样式、`.ws-work-log`、`.ws-work-log-header`。
- `app/globals.css`：字体回退、`--steer-action: #2f3036`、hover `#202126`。
- `app/fusion/page.tsx`：工作区导航、`notes` 视图入口和非聊天页面结构。
- `website/public/steer-workspace-zh-1x.png`：现有工作区截图，核对侧栏信息层级、图标尺寸与密度。
- 非聊天页 `.ws-topbar` 在桌面默认隐藏，因此本原型没有添加额外的桌面顶栏。

侧栏 260px；内容宽 `min(100% - 48px, 1040px)`；桌面顶部 30px；标题 23px / 680；界面正文 14px、控件 13px、说明 12px。背景 #fff，侧栏 #f8f9fa，侧栏选中 #e9ecf0，边框 #e8eaee，正文 #24262b，次级文字 #626773，三级文字 #9197a1。主按钮深灰；图表用现有紫色色相的低饱和变体。卡片圆角 10px，没有大面积彩色背景。图标原型为内联 SVG，正式实现使用现有 lucide 图标组件。

## 页面与交互基线

1. 页头：足迹、简短说明、生成报告。概览 / 报告两个页签。
2. 时间：今天、近 7 天、自定义；项目过滤作用于全部统计、图表和会话列表。原型「今天」固定为 2026-10-25。自定义暂限制 31 天；正式产品上限应结合数据量与报告上下文预算决定。
3. 四个统计卡：活跃会话（附新建会话数）、用户消息、Agent 回复、Token 已知用量。
4. 活动趋势：消息量默认双柱；可切换会话数、Token。点击日期仅下钻会话列表，汇总卡保持全范围；显示可清除的日期筛选。生成报告时采用当前下钻范围，并在生成面板确认显示。
5. 会话列表：会话 / 项目 / Agent、新建标识、两类消息数、Token、最近活动。按最近活动降序；会话名称打开来源预览。正式版本应定位到原会话在该范围内的消息。
6. 生成报告：520px 右侧面板；展示选中范围、会话和消息数量；输入报告名、组织方式、补充要求。草稿可编辑，附来源，可保存及导出 Markdown。
7. 来源预览可返回草稿，保留编辑内容。报告页签列出保存结果。原型保存到本浏览器 localStorage，正式实现接入工作区持久化。
8. 空范围显示空态并禁用报告生成；非法日期提示；缺失 Token 显示「未上报」，不写成零。窄屏隐藏示意侧栏、指标两列、表格横向滚动。

## 统计口径（正式实现必须保持）

- 活跃会话：范围内有用户消息或 Agent 回复的去重 session；新建会话按创建时间计数。正式系统中新建但没有消息的会话可能需要单独计入新建总数，本原型所有新会话均有消息。
- 用户消息按已发送消息实体计数；Agent 回复按完成或持久化的回复实体去重，不计每个 stream chunk，也不把工具调用当成普通回复。
- Token 是范围内 Runtime 上报的输入加输出；不能直接使用整场 session 的累计用量，以免跨日期重复累计。缓存用量按 Runtime 计量语义归一，不能把已包含在输入的缓存再叠加。无可靠时间归属的数据应明确标为无法归属。
- 会话计数跨日期需要去重，不能把每日活跃直接相加；消息和用量可在去重后累加。
- 缺失 Token 仍保留会话、消息统计，展示用量覆盖数量和「已知用量」。不同 Runtime 不支持的字段不能伪造。
- 所有日期边界按用户工作区时区；当前原型为 Asia/Shanghai。趋势统计和报告采样采用相同边界。
- 活动量不代表交付、效率或工作价值，不添加排名、生产力评分或凭消息推断的完成状态。

## 报告真实性与实现边界

原型按主题拼接示例文本，不调用 AI；补充要求仅展示，不宣称已被模型执行。正式报告应只基于授权时间范围内的消息，按项目或日期归纳，区分讨论、已执行、已验证和待办；引用具体消息，不把「讨论某功能」写成「已完成某功能」。范围之外的上下文如确需加入，应另行清晰说明。

原型侧栏的其他导航仅复现页面外壳，不连接真实功能。正式应用复用现有 Sidebar、Button、Select、Tabs 等组件，不复制一套独立导航。本目录不是生产实现。

正式接入需补齐加载、请求失败、生成中/取消/重试、权限变化、超大范围分批总结、持久化失败和重复提交处理。这些不是当前原型已验证的后端能力。

## 开发验收

以 HTML 为视觉和交互依据，截图辅助对照。优先在 1440px、1280px、390px 核对尺寸、密度、颜色与换行；不引入旧版绿色仪表盘配色。验证日期/项目一致过滤、每日下钻、未知用量、空范围、草稿编辑与来源往返、报告存取。报告面板支持 Escape、焦点限制与背景 inert；正式版关闭后恢复到有效触发控件。
