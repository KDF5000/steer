# 协作会话交互：三种备选方案

预览：http://127.0.0.1:3105/docs/prototypes/collaboration-composer-options/

三种方案复用 `../collaboration-composer/` 采集的实际工作台 DOM、生产 CSS、字体和基础交互，不修改聊天正文的字体、字重及字号。页面顶部的方案切换栏和左下角身份、权限、模拟执行按钮是演示工具。

| 方案 | 默认输入 | 发起 Agent 任务 | 适合情况 |
| --- | --- | --- | --- |
| A · 发送对象 | 发给参与者 | 输入框底部下拉选择 Builder | 希望发送前明确确认对象 |
| B · @Agent 唤起 | 发给参与者 | 输入 @ 选择 Builder，或点击 @ Agent | 讨论为主，偶尔发起任务 |
| C · 独立讨论区 | 主输入框发给 Agent | 直接发送，讨论使用独立侧栏 | 任务与讨论都多，希望分开阅读 |

共同规则：讨论不自动进入 Agent 上下文；“交给 Agent”引用原讨论，用户补充要求并主动发送。一个会话同一时间只执行一个 Agent 任务，执行期间仍可讨论。查看、讨论、执行权限分别限制可用操作。

A 切换发送对象保留输入和引用。B 的 @Builder 与正文同字体，仅颜色不同；本轮任务发送后恢复讨论，可在空输入处退格取消 @Builder。C 顶部“讨论”控制侧栏，手机以可关闭的覆盖面板呈现。

全部内容为虚构演示，状态只保存在浏览器内存，无真实邀请或任务执行。本原型聚焦操作方式，主页面中未涉及的现有控件只保留外观。正式实现应补齐消息送达、成员权限与任务状态的后端校验。

截图位于 `previews/`。浏览器检查覆盖三种方案的讨论发送、引用任务、执行期间讨论、权限限制和手机布局；B 额外验证输入 @ 后选择 Agent。
