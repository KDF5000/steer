# 个人 Workspace 下的对象共享 · 三版交互设计

日期：2026-10-26。状态：可交互 HTML 原型，正式应用未修改。

## 共同产品边界

Workspace 保持个人私有。会话与智能体授权独立，指定用户通过邮箱邀请。接收者始终在自己的 Workspace 访问共享对象，不需要切换进所有者空间。

- Session：共享同一段对话、结果和该 Session 授权执行目录。权限为可查看 / 可参与（讨论与启动 Agent）。标注发言人；讨论不自动触发执行。首版执行串行，运行期间可以继续讨论。
- Agent：共享使用权包含原 Runtime 和机器执行能力，只授权指定项目；接收者默认创建独立 Session 和 Git worktree。原机器与原生日志由提供者管理，不能承诺机器级隐私隔离。
- 共享 Agent 不授予历史 Session 阅读权；共享 Session 不授予在其他项目调用 Agent 的权利。机器列表、工具凭据、原生模型认证不向接收者展示。
- 未邀请的人不能凭一个链接获取权限；本版只做指定用户邀请，未实现公开分享、团队 Workspace 或成员组织管理。

## 三种方案

### A：集中共享入口

侧栏增加「共享给我」，分会话与智能体页签。收到邀请后在列表接受，进入共享 Session；共享能力从同一列表打开详情并创建自己的会话。

好处：共享对象容易统一查找，来源、状态与权限便于扫描。成本：日常打开共享对象多一步。

### B：融入日常工作台

侧栏单独分组「共享会话」，避免混入自己的项目。智能体页面分「我的智能体 / 共享给我」，调用共享 Agent 后产生的独立 Session 出现在个人列表。

好处：常用会话和能力更快到达，最接近现有导航习惯。成本：两个共享入口分布在不同位置，数量增多时需搜索与收起。

### C：共享收件箱

顶部收件箱接收邀请，右侧面板确认对象、权限和来源。在当前页面完成接受，回到常规会话工作流。

好处：偶尔协作时不增加固定侧栏入口，邀请上下文明确。成本：大量已接受对象的长期查找仍需补充历史列表；当前原型面板保留两个入口便于比较。

## 可体验路径

1. 所有者：聊天页「共享会话」→ 输入邮箱、选权限、发送邀请 → 成员列表修改权限、移除。
2. 顶部切换「林悦 · 接收者」，比较三版入口 → 接受共享会话 → 选择「讨论」或「发给 Agent」→ 输入与发送。
3. 所有者侧栏「智能体」→ Reviewer 的「共享能力」，查看机器、Runtime、项目和独立目录范围。
4. 接收者从共享能力入口「查看能力」→ 查看执行来源 → 接受并开始聊天 → 个人列表出现独立会话。
5. 会话顶栏「访问权限」→ 右侧面板查看权限与执行目录，退出共享。

所有交互仅改本页内存，刷新重置；邀请不调用后台，不发消息。接收者预置了一条 Session 邀请和一项 Agent 邀请，方便在未演示发送时直接对比。演示中的 Agent 执行只是状态切换，未修改代码或发起真实任务。

## 验证与限制

浏览器验证三版完整邀请、接收、讨论、Agent 使用确认、独立会话、手机宽度及控制台。权限改变、撤销与只读状态在原型中可体验，不能替代正式服务端授权验证。

实现前还需明确真实权限撤销后的运行任务处理、共享对象删除、提供者离线/容量、接收者访问目录范围，以及同一代码目录的协作锁。原型表达了权限与执行来源，不提供沙箱或凭据隔离保证。
