# 消息评论线程交互原型

预览：http://127.0.0.1:3105/docs/prototypes/message-comment-threads/

## 页面基线

复用 `../collaboration-composer/` 中采集的当前 `/fusion` DOM、生产 CSS 及字体。保持聊天消息字体、字重、状态栏、操作栏和输入框原样。仅增加消息评论入口、右侧线程及线程引用预览。输入框继续发给 Agent，不提供独立讨论模式。

## 操作

1. 用户任务消息和 Agent 回复下方均有评论图标，有评论时显示数量。图标紧邻分享按钮右侧，时间显示在评论按钮之后。
2. 点击打开该消息的评论面板。顶部显示原消息，下面按时间顺序显示评论；回复会标注所回应的评论。没有解决、未解决或审批状态。
3. 评论只用于参与者交流，不自动进入 Agent 上下文，不启动任务。Agent 执行期间可以继续评论。
4. 点击“引用整个讨论”，主输入框出现 `× | 引用 原消息摘要 · N 条评论`。已有输入保留，可以点击引用查看完整内容，也可以取消引用。
5. 用户输入本次要求后主动发送。可以直接要求执行，也可以要求先整理共识、分歧和待确认问题，平台不自动总结。
6. 发送时包含原消息、全部评论及回复关系、作者与发言顺序，并将评论标记为参考材料。引用期间新增的评论更新引用内容；实际发送时冻结快照，发送后新增评论留待下一轮。

手机使用独立覆盖面板；点击引用后自动回到主输入框。关闭面板后可以重新点击对应消息的评论数量进入。

评论面板与主聊天共用消息样式：当前用户的评论使用右侧蓝色消息，其他参与者的评论使用左侧正文；正文字号继承主聊天。被回复的评论显示灰色单行摘要，回复操作使用箭头图标。切换演示发言人时，左右身份随之更新。顶部原消息保留 Markdown 段落和列表，可收起；评论输入框沿用主输入框的圆角和发送图标。

## 演示与权限

左下角可以切换 Alex / 林悦及查看、评论、执行权限，也可以模拟任务开始和结束。查看权限不能评论，评论权限不能发起 Agent 任务，执行权限可引用和发送。

本原型使用虚构数据，所有操作只保存在当前浏览器内存。没有真实评论 API、通知、邀请、执行或数据库改动。当前演示执行者为 Builder；现有 Agent 选择控件保留正式页面外观，本轮聚焦评论与引用交互。

## 验证

浏览器检查包含生产字体和圆角基线、用户及 Agent 消息评论入口、回复关系、完整引用预览、发送前新增评论纳入、发送后新增评论隔离、执行期间评论、权限限制和手机布局。截图位于 `previews/`。
