# Steer iPhone / Apple Watch 交互审视与方案

日期：2026-11-08。范围：源码审视、三版高保真交互演示；本轮没有修改正式 SwiftUI 界面。

## 已确认的产品方向

Watch 是主要语音输入设备，也是未来 AI 助手的接收端。当前先解决抬腕查看进行中的任务数量、完成轻触提醒、语音继续同一个任务。iPhone 承接完整结果、任务浏览、设备和识别设置。语音输入设备与识别执行设备分开：Watch 收音，可以由配对 iPhone 本地转写或自托管服务转写。

## 当前问题与依据

- `apple/Phone/SteerPhoneApp.swift`：入口为 PhoneSetup，首页 Form 混合 URL、Key、配对、语音模型及诊断说明，没有日常任务首页和结果页。用户每次打开面对配置表，而不是任务。
- `apple/Watch/SteerWatchApp.swift`：首页 List 同时展示进行中、最近动态、同步状态与 DEBUG 语音验证设置；数量仅在 section 标题，抬腕辨识成本高。详情有较长摘要、展开、播放、停止与语音，主次不够明确。
- `apple/Watch/Notifications.swift` 及 App 完成 alert：已具备通知和语音续聊基础；设计应强化完成摘要到语音的直接路径，避免通知、详情、录音之间的重复阅读。
- `apple/Watch/WatchModel.swift` 与 Shared Models：已有任务状态及缓存同步信息，缺乏可靠百分比和剩余时间；新设计只展示可验证的数量、状态和最近同步时间。

以上为源码审视，未将演示图冒充现有 App 真机截图。

## 三个方案

| 方案 | 手机布局 | Watch 布局 | 取舍 |
| --- | --- | --- | --- |
| 任务台（推荐） | 进行中数量、最近完成、任务列表 | 大数字数量、简短任务入口、语音继续 | 最符合当前任务跟踪目标；多任务与语音比较平衡 |
| 收件箱 | 新结果优先，进行中作为次级入口 | 新结果数与进行中数、语音继续 | 适合批量查看结果；执行概况视觉优先级较低 |
| 语音搭档 | 当前对话及 Watch 输入状态 | 麦克风主入口、明确当前续接对象 | 更接近未来助手；多任务切换需要额外入口 |

建议以任务台落地，保留语音搭档的大触达语音操作。不要把未来开放式助手误接到当前任意任务：录音前和确认页都必须明确目标任务。

## 共同交互约束

1. 完成提醒 → 简短摘要 / 语音继续 → Watch 收音 → 识别文字确认 → 明确发送 → 已提交、等待执行。发送成功不代表已开始，不能直接增加进行中数量。
2. 当前任务被选定后再续接，保留 conversation ID 和既有 API 幂等机制。确认前不执行；取消不提交。
3. 长结果在手机查看。Watch 上“手机看完整结果”只标记待查看任务；用户打开手机 App 后再进入对应详情，不假设可强制唤起另一台设备。
4. 离线展示最近同步时间与缓存标识，转写草稿保留；恢复后仍需用户确认发送。
5. 配对、权限和模型准备属于首次设置与设置页。诊断信息移出日常首页；识别来源在确认页简短展示。
6. 完成只提醒一次；失败与完成区分；通知权限拒绝时在设置提供恢复路径。静音/专注模式下遵守系统通知行为。
7. 有执行中任务时，继续输入可能涉及排队/中断策略；正式实现必须由现有服务端语义决定。演示不承诺任意并行执行。

## 演示及验证

`steer-companion.html` 是可嵌入的三方案原型，`preview.html` 是独立浏览预览。所有任务、语音、通知、连接与发送均为本地模拟，不访问真实 API、不录音、不修改设备设置。

已在浏览器逐步验证：轮播切换三方案；完成提醒使数量 3 → 2；Watch 模拟录音 → 转写确认 → 离线保留草稿 → 重连后确认 → 发送后展示等待执行；Watch 标记任务 → 手机打开对应任务。检查 736px 双设备并排与 320px 窄屏重排，窄屏可见控件未超出容器。三版首页截图保存在 previews/。

后续正式实现仍需 iPhone/Watch 真机验证字体缩放、Digital Crown 滚动、通知冷启动路由、权限拒绝、锁屏和后台收音/转写条件；此轮没有构建或安装新 App。

## 方案 3 精简修订

用户选择语音搭档方向，并要求用布局和交互表达信息，删除注释式提示，避免大块卡片。修订入口为 `voice-companion-refined.html`，独立预览为 `voice-refined-preview.html`。

- iPhone 改为直接阅读、回复的对话页面。去掉搭档口号、操作教学、设备状态卡与重复底部导航；任务切换、设置、播放用就近操作表达。设置页也改为无填充的行列表。
- Watch 首页只呈现进行中数量、当前任务、任务状态与圆形麦克风。任务标题可切换任务，数量入口查看任务列表。
- 录音页呈现任务名、波形、时长、取消和结束；确认页呈现转写文字、重录、发送和取消；提交页呈现提交状态。必要异常状态仍保留简短文字。
- 日常产品界面无大块卡片，演示情境选择器放在设备外；收音、朗读和提交仍为模拟。
- 浏览器核对首页、录音、转写确认、完成提醒、离线保留草稿及空文字禁发。736px 并排预览与 320px 重排已检查，未发现可见控件横向溢出。首页截图为 `previews/voice-refined.jpg`。

正式 SwiftUI 尚未修改。

## 左右滑动与完成任务归档

进一步按用户建议，将 Watch 日常首页改为进行中任务的横向分页：左滑下一项、右滑上一项，页尾到边界停止；底部分页圆点兼作点击与键盘可访问入口。左右滑动通过真实指针拖动验证，两方向均更新当前任务和手机对应对话。录音时拖动不会切换目标任务。

已完成任务退出进行中分页，保留在“所有任务”的“最近完成”分组；左上角任务数量打开列表。完成提醒停留在完成结果，允许语音续接，显式返回后进入尚在执行的任务。没有执行任务时显示“全部完成”并保留列表入口。列表在固定 Watch 屏幕内纵向滚动，日常分页横向滑动。最新首页截图为 `previews/voice-swipe.jpg`。

原型仍是模拟数据，尚未改动正式 App。

## 修正：语音续接只允许已完成任务

之前原型允许进行中任务录音，违背已确认的产品规则，此节取代此前相关描述。

- Watch 横向首页顺序为进行中任务 A、B、C，最右侧固定为所有任务列表。无进行中任务时直接显示列表，不设置空白页。
- 进行中页面仅呈现任务名称、状态和分页，删除麦克风。已完成任务从列表或完成通知进入结果详情，才显示语音继续。
- 完成结果页不加入进行中分页，返回列表后可右滑回到最后一个进行中任务。
- 录音与发送动作同时检查任务可续接状态。提交后进入等待执行分组，关闭语音入口；历史结果保留，不用新一轮状态覆盖旧回复。
- 浏览器已验证连续左滑进入最右列表、列表打开完成结果、录音确认后提交以及无进行中任务时直接显示列表。静态预览为 previews/completed-voice-flow.jpg。

正式实现还必须在开始录音和提交时重新核实服务端状态；若任务已被另一设备续接，保留草稿并提示当前状态，不执行重复提交。原型仍未修改正式 App。

## 进行中页面：最近指令与运行时长

按用户反馈，进行中 Watch 页面不再只呈现状态词。现呈现任务标题、项目 / Agent、当前轮已运行时长，以及最近发送给 Agent 的用户消息。预览时长由各任务独立的模拟起始值递增，切换任务不重置计时。消息最多展示四行，点击可查看全文；详情返回保持原任务。手机对话采用同一消息内容，避免两端描述不一致。

浏览器核对了页面排版、消息全文与返回、任务切换后的消息和运行时长。截图为 previews/running-message-time.jpg。正式实现时应从当前任务的实际 startedAt 计时（不把排队时间算作运行），使用最近一条实际用户消息；若无开始时间或消息则隐藏对应字段，不编造数据。

## 定稿边界：Watch 与 iPhone 操作独立

用户暂时结束本轮设计迭代，并确认 Apple Watch 的操作不需要与手机 App 同步。此规则取代原型此前“Watch 切换任务时同步切换手机对话”的联动设计。

- 两端各自维护当前任务、导航路径、列表滚动位置以及录音/输入页面状态。Watch 切换任务、查看消息或打开完成结果，不改变 iPhone 正在查看的页面；手机操作也不推动 Watch 导航。
- Watch 语音续接绑定 Watch 当前选中的已完成任务，不依赖 iPhone 当前打开的任务。配对 iPhone 可作为转写执行设备，后台转写不要求打开或切换手机页面。
- 同一任务被续接后的执行状态与结果属于共享业务数据，由两端各自更新；不将其混同为 UI 操作同步。既有配对配置同步不受此导航规则影响。
- 本轮停止继续设计迭代。现有交互原型仍含共享 selected 状态，展示时可能联动两端；正式实现须拆分两端状态，不能照搬原型联动。此次只记录定稿边界，未修改正式 App。

## Watch 运行时长排版微调

按用户截图反馈，Watch 进行中页将时长移至项目 / Agent 同一行右侧，仅显示计时数值；删除独立计时行、时钟图标与“已运行”文字。消息紧接元信息行。此次仅调整 Watch 原型，不改变两端操作独立的定稿边界。
