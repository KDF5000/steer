# 足迹 Token 用量

Steer 消费 Relay 的统一 `usage.updated` 事件，不解析 Codex、Trae 等原生用量格式。Relay 实现与协议说明位于相邻 Relay 项目的 `docs/usage.md`。

## 保存与归属

- `run_usage` 保存真实 Run 的执行归属、Runtime、模型、用途和结束时间。新任务提交时捕获归属，同步时使用 Relay 的实际 Runtime 标识。
- `run_usage_attempts` 按 Run + attempt 保存最后一份有效快照，通过事件 sequence 阻止重复和过期响应覆盖。缓存及思考 Token 不再叠加到总量。
- 原会话中的委派结果只是展示副本，统计归属实际执行的子会话，重试的不同执行尝试分别计入。
- 活跃任务暂不计入最终足迹用量。成功、失败、取消后的已知消耗按 Relay 任务结束时间归入用户时区的日期。
- 足迹默认只汇总聊天任务。报告生成等系统任务同样保存用量，但独立分类，不混入聊天指标。
- 删除会话会随 RunLink 一起清理对应统计行；来源与租户由本地 RunLink 校验。

## 页面含义

「已知 Token 用量」是已上报数据之和，输入已经包含缓存，输出已经包含思考。未上报显示 `—` /「未上报」，实际零用量显示 `0`。「用量统计覆盖」按真实 Run 计算，存在缺失 attempt 或不完整快照时计入部分上报，不把会话数量当覆盖分母。

每日 Token 趋势和每个会话的 Token 列使用相同数据库口径。消息趋势仍按消息活动时间统计，与按任务结束日期归属的 Token 趋势可能不同。

## 同步与兼容

普通任务状态同步会保存用量。后端还运行受限、串行的后台同步队列：每批最多 20 个任务，为活跃任务和历史补算各保留 10 个位置。离开聊天页后仍会同步；足迹 API 本身只读 PostgreSQL，不触发 Relay 网络请求。

自动历史补算范围为最近 32 天，只读取已保留的标准 Usage 事件。旧 Node 从未产生标准事件的任务仍未知，不从文本、会话累计计数或模型价格猜测。

Steer 当前 Relay Go 客户端可以透传标准事件，因此本轮接入使用标准事件作为稳定输入，并同步升级 Relay SDK 和部署配置到 v0.5.7。Relay 同时提供顶层 `Run.usage` 类型。

上线需更新 Steer 前后端并执行 `000030_run_usage.sql`，同时构建和升级本次 Relay Server、Node 改动。仅升级 Steer 不会让旧 Node 自动产生用量。本轮发布 Relay v0.5.7；本地运行服务不在此次发布中重启。

## 验证

专项 PostgreSQL race 测试覆盖快照去重、过期响应、委派副本、多个执行尝试、未知/部分用量、工作区与项目隔离、系统任务排除、时区和排他日期边界，以及浏览器关闭后的后台同步。页面用演示数据验证输入/输出、覆盖、趋势、手机布局和未知与零的区分。Runtime 协议使用 fixture 验证，没有进行真实付费模型调用。
